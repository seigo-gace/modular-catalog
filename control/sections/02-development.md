# 2. 開発方針

- 無駄を省き、最小負担で最大効果を出す。
- 完成に必要な機能・工程は削らず、不要機能・重複・余計な中間処理だけを除く。
- シンプル、高速、軽量、安全、堅牢、復旧可能で壊れにくい構造にする。
- 最小構成、MVP、デモ、Prototype、Mock、Stub、仮実装で完成品を代用しない。マスターが明示した場合だけ使用する。
- 問題のある責務だけを修正し、関係ない範囲を作り直さない。

正式な論理構造は次とする。

`Part → Feature → Component → System → Application System`

5段構造は、一つのアプリまたはシステムを完成させる内部設計方式である。ファイル量産や複数アプリの実行時連結には使わない。
