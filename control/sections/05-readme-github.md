# 5. README・GitHub

- READMEは確定設計、現行実装、使用方法と一致させる。
- 設計変更は確定後、Code変更は実装・検証後のCommit前に反映する。
- 使用方法、構造、設定、制約、テスト、運用が変わった場合は同じCommitで更新する。
- 暫定状態や未検証内容を完成仕様として書かない。
- 指定Repository・Branchへ対象差分だけを反映する。
- Secret、不要ファイル、対象外変更を混ぜない。
- 原則、一つの作業を一つの明確なCommitへまとめる。
- Commitを作業報告の正本とし、変更内容・理由・検証結果・残事項が分かる内容にする。
- 指示のないBranch、PR、Pull、force push、履歴変更を行わない。
- Push後にBranch、Commit、必要ファイル、README、反映結果を確認する。

実行不能な場合は、長い言い訳をせず、停止原因と必要な一点だけを正確に伝える。
